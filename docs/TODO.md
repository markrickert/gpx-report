- [ ] **Delete/archive an activity.** No delete path exists anywhere — no mutation, no resolver, no UI. Deletes the source file from `data/gpx/` as well as the DB row (not a DB-only hide), so the watcher/re-analysis don't re-ingest it on restart/rescan.

- [ ] **Reverse-geocoded location name per activity.** Resolve the start point's lat/lon to a place name (city/trailhead) via a geocoding API and show it on the Dashboard list / Activity Detail header instead of just date+type. - [ ] **Bulk actions on the Dashboard.** Multi-select activities to retype or delete in one operation (depends on the delete mutation above existing first), instead of the current one-at-a-time inline editing on each Activity Detail page.
- [ ] **Push/toast notification when a new activity finishes ingesting.** Currently the only feedback that a synced file was processed is seeing it appear in the Dashboard list. - [ ] **GPS outlier detection is too sensitive.** User-reported: the existing manual/opt-in outlier flagging (`backend/src/track/outliers.js`'s `detectOutliers()`, fixed >55 m/s / ~200 km/h jump threshold) is flagging points that shouldn't be flagged. Needs investigation before a fix — check whether the threshold itself is too low for some real-world GPS behavior (e.g. legitimate downhill biking/driving speeds, or brief GPS jumps that self-correct) or whether the detection logic has a bug, before just raising the number.

- [x] **Elevation profile smoothing** (2026-08-07) — new `backend/src/track/elevation.js`'s `computeElevationGainLoss()` runs a centered 5-point moving average over each track's elevation values before summing gain/loss, used by the GPX/IGC/`.skiz` parsers in place of their previous raw-delta sums. Only `total_elevation_gain`/`total_elevation_loss` are affected — `points_data`/`elevation_profile_data` (the chart, map, grade-adjusted pace, lift/outlier detection) still store and read raw per-point elevation, unchanged. Tracks with 5 or fewer points fall back to raw deltas (a centered average over that few points flattens real elevation change to near-zero). Backfilled across all existing activities by rebuilding and restarting the backend (file watcher re-ingests every pre-existing file on startup, same idempotent upsert path `reanalyzeAllActivities` uses).
- [x] **Two-finger rotate gesture on the activity map** (2026-08-07) — `ActivityDetail.jsx`'s main map gets `leaflet-rotate` (its `rotate`/`touchRotate` map options) wired into the existing `MapContainer`, enabling two-finger touch rotation plus its desktop equivalent (shift+scroll wheel) for free; the existing reset-view button now resets bearing back to north alongside its existing pan/zoom reset. `leaflet-rotate` patches Leaflet by mutating a bare global `L` rather than importing it, so a small `leafletRotateSetup.js` puts `L` on `window` before the plugin loads. Since the patch is global to the `L.Map` class, the plugin's own built-in compass control (`rotateControl`) and its default-on `shiftKeyRotate` handler are explicitly disabled (`rotateControl={false}`) on every other `MapContainer` in the app (Record, Heatmap, the outlier-cleanup map) so they don't pick up unwanted rotate UI/behavior just from the plugin being loaded elsewhere.

Exposed as `movingAvgSpeedMps` on the `Activity` GraphQL type and shown as a new "Moving Speed" stat tile on `ActivityDetail.jsx` next to the existing "Avg Speed" tile. - [x] **Auto-suggested crop for lead-in/trailing inactivity** (2026-08-07) — entering trim/edit mode on `ActivityDetail.jsx` now pre-positions the trim handles at a suggested crop instead of the full track: walks in from each end while `elevationProfile[i].speedMps` stays under the existing `REST_SPEED_THRESHOLD_MPS` (the same constant the rest-stop-band detector already uses), only committing to a crop if that stillness lasted at least 30 seconds (measured via point timestamps on `route.coordinates`, not raw point count, since recording interval varies by device) at that end; falls back to the full-track range if neither end has a long-enough still stretch. A small min/max speed legend with a matching gradient bar sits under the map. - [x] **Grade-adjusted pace** (2026-08-07) — new "Grade-Adjusted Pace" metric tile on `ActivityDetail.jsx`, computed entirely client-side from the existing `route.elevationProfile` (`distanceMeters`/`elevation`/`speedMps`, no schema/backend change). Per-point grade is noisy at the raw ~0.5m point spacing some tracks have, so consecutive points are accumulated into ≥10m horizontal-distance windows before computing grade; each window's average speed is scaled by a grade-cost multiplier from Minetti et al. 2002's published metabolic-cost-of-running polynomial (normalized to flat-ground cost), then time-weighted across the whole track for the tile's single average value. Grade is clamped to ±45% (the range Minetti's polynomial is fit over). Verified against a real hilly hike (1.3 mph avg speed → 2.5 mph GAP) and a flat control activity (GAP ≈ avg speed, as expected at ~0% grade).

## Known gaps

- [ ] **No DB migration tooling.** `backend/db/init.sql` only runs against a fresh volume. Any schema change to an already-deployed instance needs a manual `psql`/`ALTER` step. Fine for now (single-user, low change rate) but worth a lightweight migration runner if schema churn picks up.
- [ ] **No typecheck config anywhere in the repo.** ESLint/Prettier and backend parser unit tests now exist (see Done above); typechecking is still unaddressed, and frontend/GraphQL-layer test coverage remains thin.
- [ ] **No auth on the API or frontend.** Acceptable for now since the intended deployment is Caddy + Tailscale (see `docs/SETUP.md` §6 reverse-proxy notes), but if the API/frontend domains are ever exposed outside Tailscale, this becomes a real gap, not just a v1 simplification.
- [ ] **Node 18 is stale and breaks tooling.** Both the host/dev environment and the Docker base images are pinned to Node 18; Vitest's `rolldown` dependency needs `node:util`'s `styleText` export (Node ≥20), so `backend && npm test` currently fails to even start outside a Node 22 shell. Upgrade the Docker base images (`backend/Dockerfile`, `frontend/Dockerfile`) and any documented dev-environment Node version to a current LTS (22.x).

## Explicitly out of scope for v1 (not gaps, just noting so they don't get re-litigated)

- No in-app GPX upload/file management — files are expected to arrive via Syncthing or manual drop into `data/gpx/`.
- No multi-user support.
- No graceful degradation without JavaScript. The frontend is a pure client-rendered Vite/React SPA — JS disabled means a blank page. Fixing this needs SSR/static pre-rendering, a genuine architecture shift not warranted for a personal single-user tool.
