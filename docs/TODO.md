- [x] **Edit activity title, written back to source GPX file** (2026-08-06) — added `updateActivityTitle(id, title)` GraphQL mutation (`backend/src/graphql/{typeDefs,resolvers}.js`), a new `backend/src/gpx/writer.js` (`updateGpxTitle`) that rewrites the `<trk><name>` element in the source `.gpx` file via string replacement (no XML DOM lib added), then re-runs `processFile()` so the DB row and GPX file stay in sync. Frontend: `ActivityDetail.jsx` has an inline Edit/Save/Cancel affordance on the title. Only the title is editable for now — other metadata fields weren't asked for.
- [x] **Browser-based file viewer/editor** (2026-08-06) — asked for a simple read-only docs viewer with git history first; built it (`/docs` page + `repoTree`/`repoFile`/`fileHistory`/`fileDiff` GraphQL resolvers), then superseded it in the same session with a `code-server` service (`docker-compose.yml`) once write access became the actual goal — full VS Code in the browser, bind-mounted read-write at the repo root, port 8443, `--auth none` (Tailscale-only, no public exposure). The custom viewer code was removed rather than kept alongside it. See `docs/SETUP.md` §7.
- [x] **Code-server exposed as a tab in the frontend** (2026-08-06) — added a "Code" nav link / `/code` route (`frontend/src/pages/CodeEditor.jsx`) that iframes the existing code-server container at `http://<current-hostname>:8443`, derived at runtime from `window.location.hostname` (no build-time config, matching whatever host the app itself was loaded from). No new Caddy site or exposure — same LAN/Tailscale-only reach code-server already had, just one click away from the dashboard instead of a separate bookmark/port.
- [x] **Code tab switched to https via a Caddy site** (2026-08-06) — the runtime-derived `http://<hostname>:8443` iframe got blocked as mixed content once the dashboard was loaded over the public https domain. Added a `gpx-report-code.example.com` Caddy site (`reverse_proxy localhost:8443`, same pattern as the GraphQL API site) and a `VITE_CODE_SERVER_URL` build arg (baked in at image build time, matching `VITE_GRAPHQL_URL`) so the iframe loads over https. Still `--auth none` and Tailscale-only reach — the domain doesn't resolve/route outside Tailscale on this deployment, so the trust boundary is unchanged, just no longer mixed-content-blocked. See `docs/SETUP.md` §7. Also fixed the Code tab and dashboard content being narrower than the viewport (a stray `margin: 0 auto` and an overly tight 960px cap in `frontend/src/styles.css`).

- [x] **Dashboard activity list route thumbnail** (2026-08-06) — each row in `frontend/src/pages/Dashboard.jsx` now renders a small SVG polyline of the route shape next to the title/meta, built client-side from `activity.route.coordinates` (normalized to a 48x48 box, no basemap). Not a real Leaflet map: rendering 50 live tile-based maps per dashboard load would hammer OpenStreetMap's tile servers and be slow; a plain SVG sparkline needs no tiles and stays cheap at this scale. `GET_DASHBOARD` now also fetches `route { coordinates }` per activity.
- [x] **Dashboard infinite scroll** (2026-08-06) — `Dashboard.jsx` fetches `PAGE_SIZE=50` activities at a time and loads more automatically via an `IntersectionObserver` on a sentinel element at the bottom of the list, appending pages to local state as the user scrolls (rather than a fixed 50-activity cap with no way to reach older ones). Resets to page one when the activity-type filter changes since `useQuery`'s variables change. `GET_DASHBOARD` now takes `$limit`/`$offset`.
- [x] **Tighter Y-axis range on the elevation profile** (2026-08-06) — `ActivityDetail.jsx`'s elevation `LineChart` `YAxis` now uses an explicit `domain` of `[min elevation - 10, max elevation + 10]` (computed from `elevationData`) instead of the default 0-based domain, so variation is visible even when the route stays well above sea level. Falls back to `[0, "auto"]` if the profile is empty.
- [x] **Entrance animation for dashboard list items on scroll** (2026-08-06) — `Dashboard.jsx` rows start `opacity: 0`/translated down 12px and fade+slide to normal via a shared `IntersectionObserver` (a callback ref on each `<li>` observes it once on mount, adds its id to `visibleIds` state and unobserves on first intersection — matches the existing sentinel-observer pattern already used for infinite scroll). Applies to newly loaded pages too since new `<li>`s get their own ref call. Respects `prefers-reduced-motion` (`frontend/src/styles.css`).

## Known gaps

- [ ] **`aggregatedStatsByType` query is unused.** It's fully implemented in the resolvers/schema but no frontend page calls it — there's no per-activity-type breakdown view (e.g. "total running distance this year").
- [ ] **No DB migration tooling.** `backend/db/init.sql` only runs against a fresh volume. Any schema change to an already-deployed instance needs a manual `psql`/`ALTER` step. Fine for now (single-user, low change rate) but worth a lightweight migration runner if schema churn picks up.
- [ ] **No automated tests, lint, or typecheck config anywhere in the repo.** Noted as current state in `CLAUDE.md`; flagging here as something to eventually add rather than silently keep deferring.
- [ ] **No auth on the API or frontend.** Acceptable for now since the intended deployment is Caddy + Tailscale (see `docs/SETUP.md` §6 reverse-proxy notes), but if the API/frontend domains are ever exposed outside Tailscale, this becomes a real gap, not just a v1 simplification.

## Explicitly out of scope for v1 (not gaps, just noting so they don't get re-litigated)

- No in-app GPX upload/file management — files are expected to arrive via Syncthing or manual drop into `data/gpx/`.
- No multi-user support.
